# Architecture Decision Records

## 철학
수요 검증이 MVP의 유일한 목표다. 검증에 필요 없거나 없어도 사용자가 불편하지 않은 것은 만들지 않는다. 대신 돈(AI 비용)과 데이터 무결성(한도, 레벨, 지표)에 관한 규칙은 DB 트랜잭션으로 확실히 지킨다. 상세 근거는 `docs/spec/plan.md` 8장.

---

### ADR-001: Next.js App Router + Supabase + Vercel
**결정**: Next.js(App Router, TypeScript strict, Tailwind)를 Vercel(icn1)에, Supabase(Auth 구글·Postgres·RLS, 서울)를 DB로 쓴다.
**이유**: 한 저장소에서 페이지와 API를 함께 만들고, 인증·RLS를 직접 구현하지 않는다. 사용자와 같은 지역이다.
**트레이드오프**: Supabase 무료 플랜은 7일 무요청 시 일시정지되고 백업이 제한적이다. 배포 전 `supabase db dump`로 대비한다.

### ADR-002: use-case 레이어(`src/server/`)와 의존성 주입
**결정**: route는 얇게 두고, 비즈니스 규칙은 `{ db, ai }`를 주입받는 use-case에 둔다. 판단 없이 RPC 하나만 부르는 API는 route가 `server/db`를 바로 부른다. DB 인터페이스는 트랜잭션 단위다.
**이유**: 분기·호출 순서를 Docker 없이 가짜 구현으로 빠르게 테스트하고, Stop hook(lint·build·test)을 통과시킨다.
**트레이드오프**: 잠금·RLS·원자성은 가짜로 증명할 수 없어서 `test:db`(로컬 Supabase) 통합 테스트를 따로 유지한다.

### ADR-003: 여러 행의 판정은 RPC 트랜잭션 + 계정 잠금
**결정**: 한도·세션 상태·레벨·활동일·연속일의 판정과 변경은 RPC 하나로 묶고, 먼저 `profiles` 행을 `FOR UPDATE`로 잠근다. 모든 경로가 같은 잠금 순서를 쓴다.
**이유**: 두 탭·두 언어의 동시 요청이 한도를 넘거나 연속일을 덮어쓰지 않게 한다. HTTP로 분리된 조회·변경은 원자적이지 않다.
**트레이드오프**: 로직 일부가 SQL 함수로 가고, 마이그레이션과 실행 권한 관리가 필요하다.

### ADR-004: 대화 턴은 예약 → AI → 확정, 작업 토큰 90초
**결정**: 예약 RPC가 pending 턴과 세션 작업 토큰(90초 기한)을 만들고 커밋한 뒤 잠금 밖에서 Claude를 부른다. 확정 RPC는 토큰·기한이 맞을 때만 저장한다. 세션당 pending 1개를 partial UNIQUE로도 보장한다. 정리용 cron 없이 다음 요청에서 만료 작업을 복구한다.
**이유**: AI 호출(최대 약 40초) 동안 DB를 잠그지 않으면서 동시 전송·늦게 도착한 응답이 한도와 결과를 망치지 않게 한다.
**트레이드오프**: 상태가 늘어난다. 네트워크 끊김 후 같은 메시지 재전송 중복은 감수한다(멱등 키 없음).

### ADR-005: 세션 종료는 active → ending → ended, 실패 시 대체 결과
**결정**: `/end`는 멱등이다. `ending` 예약을 얻은 요청만 Claude로 피드백을 만들고, 처리 중 재요청은 202, 실패·기한 만료는 고정 대체 결과(fallback)로 끝낸다. 0턴 세션은 AI 없이 skipped로 끝낸다.
**이유**: 동시·반복 종료 요청이 AI를 중복 호출하지 않게 한다. `ending` 제거도 검토했지만, 같은 방어를 하려면 결국 비슷한 상태가 필요해서 유지했다.
**트레이드오프**: 202 재확인 처리가 클라이언트와 래퍼에 들어간다. 대체 결과 확정 후 피드백 재생성은 하지 않는다.

### ADR-006: Claude Haiku 4.5 + 구조화 출력, 스트리밍·캐싱 없음
**결정**: 기본 모델은 `claude-haiku-4-5-20251001`(환경변수로 변경). `client.messages.create()` + 구조화 출력(`output_config.format`)으로 받고, `stop_reason`을 먼저 본 뒤 zod로 `{ reply, reply_ko, correction }`을 파싱한다. SDK 재시도는 끄고 직접 1번 재시도한다.
**이유**: 대화 1회 약 $0.004로 비용이 낮다. 프롬프트가 Haiku 4.5의 캐시 최소 길이(4096토큰)에 못 미칠 가능성이 크다.
**트레이드오프**: 응답을 한 번에 받아 체감 대기 시간이 있다. 일본어 교정 품질은 출시 전에 샘플로 확인한다.
**변경**: 모델은 ADR-012에서 Claude Sonnet 5.5로 바꿨다.

### ADR-007: 사용량은 원본 행으로 계산, 한도는 계정 단위
**결정**: 별도 카운터 없이 오늘 `chat_turns`(pending 포함)와 `first_seen_at`이 오늘인 `user_words`를 센다. 언어를 합산하고 한국 자정(UTC+9)에 초기화한다.
**이유**: 카운터와 원본이 어긋날 일이 없다. pending을 포함해 동시 예약도 한도를 넘지 않는다.
**트레이드오프**: 만료된 pending이 복구 전까지 표시 사용량에 남는다. 그래서 입력은 서버 429 뒤에만 막는다.

### ADR-008: 단어는 미리 생성, 빈칸은 4지선다, 레벨업은 서버 채점
**결정**: 언어 × 레벨 200개를 스크립트로 생성해 검수 후 커밋하고 seed한다. 빈칸은 모든 레벨 4지선다로 문자열을 그대로 비교한다. 레벨업 테스트는 서버가 채점한다.
**이유**: 학습 중 AI 비용이 없고, 정규화·직접 입력 채점이 필요 없다. 레벨 변경은 어차피 서버에서 해야 한다.
**트레이드오프**: `words`는 읽을 수 있는 테이블이라 부정은 완전히 막지 못한다(본인 손해로 허용). 단어 2,000개 검수 부담이 있다.
**변경**: 빈칸 정답 설명은 ADR-013에서 요청 시 AI로 만들기로 했다. 학습 자체에는 여전히 AI 비용이 없다.

### ADR-009: 지표는 서버 기록만, 로컬 스크립트로 계산
**결정**: 이벤트는 다른 테이블로 알 수 없는 것만 남긴다. 학습한 날은 `user_activity_days`에 남기고, 방문 추적은 하지 않는다. 유효한 대화 세션은 성공 턴 3개 이상(종료 무관). `scripts/metrics-report.ts`가 `lib/metrics`로 분자/분모를 계산한다.
**이유**: 판단 기준은 서버가 기록한 학습만 쓴다. 클라이언트 방문 기록은 누락·조작 가능성이 있고 구현 비용이 크다.
**트레이드오프**: 가입 전 퍼널과 단순 재방문율은 볼 수 없다. 대시보드가 없어서 지표는 로컬에서 실행해 확인한다.

### ADR-010: 동의·준비 상태는 페이지와 API 모두에서 검사
**결정**: 온보딩 필수 체크 1개로 동의를 받는다. 보호 페이지는 `/onboarding`으로 보내고, API는 래퍼와 쓰기 RPC에서 403(`CONSENT_REQUIRED`, `ONBOARDING_REQUIRED`)을 반환한다. 예외는 consent·levels·language 3개뿐이다.
**이유**: 페이지 이동만으로는 API 직접 호출을 막을 수 없다.
**트레이드오프**: 모든 쓰기 경로에 준비 상태 검사가 들어간다.

### ADR-011: 환경은 로컬 Docker + 클라우드 prod 1개
**결정**: 로컬은 Supabase CLI(Docker), 운영은 Supabase 클라우드 1개와 Vercel Production. Vercel Preview는 끈다.
**이유**: dev DB가 없으므로 Preview가 prod DB를 써서 지표를 오염시키는 것을 막는다.
**트레이드오프**: 배포 전 검증은 로컬에서만 한다.

### ADR-012: 대화 모델을 Claude Sonnet 5.5(effort low)로 변경
**결정**: 기본 모델을 `claude-sonnet-5-5`로 바꾸고 `output_config.effort = "low"`, `max_tokens` 4096으로 부른다. thinking은 지정하지 않는다(adaptive). 구조화 출력·재시도·실패 처리는 ADR-006 그대로다.
**이유**: 2026-10-08에 일본어 13문장(레벨 1~5)을 같은 프롬프트로 비교했다. Haiku 4.5는 후리가나 누락 4건과 깨진 표기 1건, 교정 누락(`熱もあるです`, `遅くしても`), 이름 표기 오류가 있었다. Sonnet 5.5는 교정 대신 다음 대사를 제안한 1건 말고는 문제가 없었고, 응답 시간은 평균 약 3.7초로 Haiku와 비슷했다. `low`에서는 13문장 모두 thinking 없이 답해 thinking을 끈 설정과 비용이 같았다.
**트레이드오프**: 턴당 비용이 약 2배다(일본어 약 $0.0036 → $0.0074). 지금은 결제가 없어 검증 기간 비용만 늘지만, Pro(월 9,900원, 하루 150턴)는 많이 쓰는 사용자에게 적자가 날 수 있어 결제 전에 프롬프트 캐싱과 Pro 한도를 다시 본다. effort를 받지 않는 모델(Haiku 4.5)로 env를 바꾸면 모든 호출이 실패한다.

### ADR-013: 빈칸 정답 설명은 요청 시 AI로 만들고 저장하지 않는다
**결정**: 단어 학습 빈칸(채점 뒤)과 오답 복습 카드 뒷면에서 요청하면 `POST /api/words/explain`이 대화와 같은 모델로 설명을 만든다. 결과는 저장하지 않는다. 예약 RPC가 계정 잠금 안에서 실패 10회와 Free 하루 20회를 확인하고 `word_explained` 행을 남기며, 실패하면 그 행을 지우고 `chat_failed`를 남긴다. Pro는 무제한이다. 한도 거부는 `limit_reached`로 남기지 않는다.
**이유**: 단어 데이터에 미리 만들면 2,000개 생성·검수·마이그레이션·seed가 필요하다. 요청 시 생성은 데이터와 생성 스크립트를 바꾸지 않고, 고른 오답에 맞춘 설명을 줄 수 있다. `limit_reached`를 남기면 체험 전환 지표의 `feature` 정의가 바뀐다.
**트레이드오프**: 설명마다 AI 비용(약 $0.004 추정)이 들고, 사람이 검수하지 않은 설명이 나간다. 같은 단어를 다시 풀면 다시 센다. Pro 무제한은 API 직접 반복 호출을 막지 못해 Anthropic 지출 한도에 기댄다.
