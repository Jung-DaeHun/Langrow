# 음성 (TTS) (2026-10-12 추가)

- **목적**: 학습자가 단어·예문·가나·대화 문장의 실제 발음을 듣는다.
- **방식**(ADR-014): 단어·예문·가나는 데이터가 고정돼 있으므로 Azure Speech로 **미리 만든 mp3를 저장소에 커밋**해 모든 사용자가 같은 음성을 듣는다. 대화 문장은 매번 달라 미리 만들 수 없으므로 **브라우저 음성(Web Speech API)**으로 읽는다. 서버·DB·API는 바꾸지 않는다.
- **비용**: 0원. Azure 무료 등급(F0, 월 50만 자)만 쓰고, 운영 앱은 Azure를 부르지 않는다.

## 미리 만드는 음성
- **파일** (`public/audio/{음성}/`, 약 4,071개, 정적 파일로 배포)
  - 첫 폴더는 음성 종류다. 지금은 `female`만 만든다. 남성 음성은 나중에 `male/`로 같은 구조를 추가한다(아래 "나중에: 남성 음성").
  - 단어: `female/words/{word_id}.mp3` / 예문: `female/words/{word_id}-ex.mp3` (단어 2,000개 × 2)
  - 가나: `female/kana/{히라가나 코드포인트 16진수 소문자}.mp3` (예: あ → `3042.mp3`) 71개. 가타카나는 소리가 같은 히라가나 파일을 쓴다(코드포인트 − 0x60).
  - 형식: `audio-24khz-48kbitrate-mono-mp3`
- **읽을 내용**(`src/lib/audio.ts`, 순수 함수): 문장마다 SSML 문서 하나를 만든다. 글자는 XML 이스케이프한다.
  - 영어 단어: `word` 그대로 / 영어 예문: `example`에서 `{{`·`}}`를 지운 문장
  - 일본어 단어: `word`에 한자가 있고 `reading`이 다르면 `<sub alias="{reading}">{word}</sub>`, 아니면 `word` 그대로
  - 일본어 예문: `{{`·`}}`를 지우고 `parseFurigana`의 읽기가 있는 조각을 `<sub alias="읽기">본문</sub>`으로 바꾼다(예: `[答|こた]えが{{[違|ちが]って}}います。` → `<sub alias="こた">答</sub>えが<sub alias="ちが">違</sub>っています。`). 데이터의 후리가나대로 읽게 해서 한자를 잘못 읽지 않게 한다.
  - 가나: 히라가나 글자 하나
  - 음성: `female` = 영어 `en-US-AvaNeural`, 일본어 `ja-JP-NanamiNeural`. 바꾸면 이 문서와 스크립트 상수를 고친다.
- **생성 스크립트** `scripts/generate-audio.ts` (`npm run audio:generate`)
  - `data/words/*.json`과 `src/lib/kana.ts`로 위 목록을 만들고, Azure REST(`https://{region}.tts.speech.microsoft.com/cognitiveservices/v1`)를 `fetch`로 부른다. SDK는 쓰지 않는다.
  - 키는 로컬 `.env.local`의 `AZURE_SPEECH_KEY`·`AZURE_SPEECH_REGION`에만 둔다. 운영(Vercel) env와 앱 코드는 이 키를 쓰지 않는다. 없으면 Azure를 부르지 않고 실패한다.
  - `data/audio-manifest.json`에 파일 경로별로 SSML 문서(음성 이름 포함)의 해시를 적는다. 파일이 없거나 해시가 다른 것만 만든다. 그래서 중간에 끊겨도 다시 돌리면 이어서 만들고, 단어를 고치거나 음성을 바꾸면 바뀐 것만 다시 만든다. 파일 하나를 쓸 때마다 manifest도 갱신한다.
  - F0는 분당 20회라 요청 사이를 3초 이상 띄운다. 처음 전체 생성은 약 3.4시간이다. 429는 `Retry-After`(없으면 60초)만큼 기다렸다가 같은 항목을 다시 보낸다. 그 밖의 오류 응답이나 빈 응답이면 그 자리에서 멈춘다(이미 만든 파일과 manifest는 남는다).
  - `-- --ids <word_id|가나>,...`로 일부만 만들 수 있다(샘플 확인용).
  - 과금 글자 수는 SSML 태그를 포함하고 한자를 2자로 센다(Azure 과금 규칙). 전체는 약 14.3만 자라 무료 한도 안이다. 같은 달에 전체를 세 번 다시 만들면 한도를 넘어 요청이 거부된다(F0는 과금하지 않는다).
- **샘플 확인(전체 생성 전 한 번)**: 까다로운 단어·예문·가나 10개 정도를 `--ids`로 만들어 사람이 듣는다. 영어 음성을 고르고, 일본어 `<sub>` 읽기 지정이 억양을 해치지 않는지 확인한다. 억양이 크게 어색하면 전체 생성 전에 방식을 다시 정한다.
  - 2026-10-12에 18개(일본어 `<sub>` 있음/없음 3쌍, 한 단어가 `<sub>` 둘로 쪼개지는 `取り扱う` 포함, 숫자, 가나 한 글자, 영어 Ava·Jenny·Andrew, 일본어 Nanami·Keita)를 들어 문제없음을 확인했다. 음성은 기본값(Ava·Nanami)을 유지한다.
- **어긋남 검사**(`npm run test`): 만드는 음성(지금은 `female`)의 모든 단어·가나에 대해 파일이 있고, manifest 해시가 지금 데이터로 만든 SSML의 해시와 같은지 확인한다. 사람 검수로 단어를 고친 뒤 음성을 다시 만들지 않으면 실패한다. 그래서 단어를 고치려면 Azure 키가 필요하다.
- 스크립트는 데이터에 없는 파일을 지우지 않는다. 단어를 지우면 그 파일과 manifest 항목을 직접 지운다.
- 인증 가드(`src/proxy.ts`)는 이미지처럼 `.mp3`도 제외한다. 재생마다 로그인 확인을 하지 않는다.

## 대화 음성 (브라우저)
- AI 말풍선(첫 마디 포함)과 교정 카드의 고친 문장을 읽는다. 읽을 문장은 `stripFurigana`로 표기를 지운 본문이다. 브라우저 음성에는 읽기를 지정할 수 없어 한자를 잘못 읽을 수 있다. 알려진 한계로 받아들인다.
- 음성은 `speechSynthesis.getVoices()`에서 고른다. `lang`을 `-`/`_` 구분 없이 비교해 `en-US`/`ja-JP`와 같은 것을 먼저, 없으면 `en`/`ja`로 시작하는 첫 음성을 쓴다.
- **맞는 음성이 없거나 `speechSynthesis`가 없으면 버튼을 그리지 않는다.** 기본 음성으로 대신 읽으면 일본어를 영어 음성으로 읽게 된다. 음성 목록은 늦게 올 수 있어서 `voiceschanged` 뒤에 다시 고른다. 서버 렌더링 때는 그리지 않는다.
- 문장은 우리 서버를 거치지 않는다. 브라우저에 따라 그 브라우저 회사의 음성 서버로 보낼 수 있다.

## 재생 규칙 (`SpeakButtons`, 화면 규격은 `ui.md` "음성 재생")
- 누를 때만 재생한다. 자동 재생은 하지 않는다.
- 버튼은 [듣기]와 [천천히 듣기] 두 개다. 천천히 듣기는 파일을 `playbackRate = 0.75`(음 높이 유지), 브라우저 음성을 `rate = 0.75`로 재생한다.
- 누르면 처음부터 재생한다. 재생 중에 다시 눌러도 처음부터 다시 한다.
- 페이지에서 소리는 하나만 난다. 다른 버튼을 누르면 앞 소리를 멈춘다. 버튼이 사라지면(카드를 뒤집거나 넘김, 다음 문제, 화면 이동) 그 버튼의 소리를 멈춘다.
- 재생에 실패하면(파일을 못 불러옴, `play()` 거부, 음성 오류) 버튼 아래에 오류 문구를 보여 주고 다시 누르면 지운다. 우리가 멈춰서 생긴 음성 중단(`interrupted`·`canceled`)은 오류로 보지 않는다.
- 재생은 이벤트를 남기지 않는다(`metrics.md`: 다른 테이블로 알 수 없는 것 중 지표에 쓰는 것만 남긴다). 사용량에도 들어가지 않는다.

## 위치
| 화면 | 재생 내용 |
|---|---|
| 단어 학습·오답 복습 카드 | 앞면은 단어, 뒷면은 예문 파일 |
| 가나 카드 | 글자 파일(앞·뒷면 같음) |
| 빈칸 퀴즈(단어 학습) | 채점 뒤에만 예문 파일. 채점 전에는 정답이 드러나서 두지 않는다 |
| AI 대화 | AI 말풍선(첫 마디 포함), 교정 카드의 고친 문장(브라우저 음성) |

- 레벨업 테스트는 빈칸 퀴즈를 같이 쓰지만 채점 화면이 없어서 버튼이 나오지 않는다. 종료 피드백에는 두지 않는다.

## 합성 음성 고지
- Azure 이용 규정(Code of conduct for text to speech)은 사용자가 알아볼 수 있게 합성 음성임을 알리고, 문제를 알릴 창구를 두도록 요구한다.
- `/words` 시작 카드와 `/kana` 제목 아래 안내 문구에 "발음은 합성 음성이에요"를 붙인다. 창구는 약관·개인정보처리방침의 문의 이메일(`site.config.ts`)이다.

## 나중에: 남성 음성 (2026-10-12 결정, 아직 만들지 않음)
- 지금은 여성 음성만 쓴다. 남성 음성을 넣을 때는 아래처럼 한다.
- `male` = 영어 `en-US-AndrewNeural`, 일본어 `ja-JP-KeitaNeural`(2026-10-12 샘플로 들어 봄). `public/audio/male/`에 같은 구조로 만든다. 파일 약 4,071개, 약 3.4시간, 과금 약 14.3만 자가 더 든다. 두 음성을 합치면 약 28.6만 자라 같은 달에 둘 다 전부 다시 만들 여유는 없다.
- 설정은 계정에 저장한다(`profiles` 컬럼, `PUT /api/me/language`와 같은 형태의 API). 새 `/settings` 페이지에서 고르고, 기본값은 여성이다.
- 대화 문장은 설정과 무관하게 기기 음성으로 읽는다. 브라우저 음성 목록에는 성별 정보가 없다.
